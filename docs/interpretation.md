# 해석 — 무엇을 어디까지 보는가

> 계산이 맞는 것과 잘 읽어주는 것은 다른 문제다.

[← 명리서재](../README.md)

## 각 기능의 모델 깊이

정직하게 적어둔다. 이 프로젝트가 실제로 판 건 **만세력 정확도 하나**다.

| 기능 | 모델 | 깊이 |
|---|---|---|
| **만세력 · 대운** | tzdata 표준시 이력 + 진태양시 + 절기 분 단위 + 대운수 + 순역 + **십이운성** | **깊음.** 골든 50건 + 십이운성 120조합 교차 검증 |
| **궁합** | 일간 오행 + 일지(육합·삼합·충·형) + 오행 보완 + 상호 십성 | 보통. 12자 전부 사용 |
| **신년** | 세운 십성 + **지금 대운과의 합충 관계** | 보통 |
| **원국 해석** | 궁위 + 오행 균형 + 지장간 + 공망 + 십이운성 + 신강신약·용신 + **신살 13종** | 보통. 여덟 자 전부 사용 |
| **오늘** | 일진 천간·지지 십성 + 십이운성 + 내 일지와의 합충 | 보통 |

### 십이운성을 대운에 넣은 이유

대운 칸이 간지와 십성만 보여주면 "그 10년에 무슨 일이 있나"는 알려주지만
"그때 내가 힘이 있었나"는 말해주지 않는다. 같은 편관 대운이어도 건록·제왕
자리면 밀어붙일 힘이 있고, 절·묘 자리면 버티는 시기가 된다.

각 칸에 막대로 표시한다. **점수가 아니다** — 십이운성 열두 자리를 길이로
옮긴 것이고, 절·묘가 짧은 건 나쁘다는 뜻이 아니라 밖으로 뻗는 힘이 약한
대신 안으로 여무는 시기라는 뜻이다. 그래서 변수 이름도 `strength` 가 아니라
`outwardness` 다.

표(10간 × 12지)는 직접 만들었고, `lunar-javascript` 가 원국 지지에 대해
주는 값과 **120개 조합에서 대조**해 검증한다. 표가 한 칸이라도 틀리면
테스트가 잡는다.

### 원국을 여덟 자 전부로 읽는다

원본은 십성 카테고리를 세어 가장 많은 하나(dominant)로 성격과 직업을
결정했다. 여덟 자를 계산해놓고 카운트 하나로 뭉갠 셈이다.

- **궁위** — 같은 관성도 년주면 집안의 규율이고 시주면 자식·말년의 책임이다.
  네 기둥이 각각 인생의 한 시기를 맡는다.
- **지장간** — 지지 속에 숨은 천간. 라이브러리가 배열로 주는데 `[0]`만 쓰고
  있었다. 월지는 셋까지 나온다.
- **공망** — 비어 있는 자리. 그 궁위의 일이 헛돌기 쉽다고 본다.
  라이브러리 `getDayXunKong()` 과 대조 검증한다.
- **오행 균형** — 없는 오행과 넘치는 오행(넷 이상). 화면에만 있고 해석
  문장에는 안 쓰이고 있었다.

### 용신 — 억부용신법을 쓰고, 그 사실을 밝힌다

명리에는 용신을 잡는 방법이 여럿이다 (억부·조후·병약·통관·전왕).
그중 실무에서 가장 널리 쓰이는 **억부용신법**을 쓴다. 일간이 강하면
눌러주고 약하면 도와주는 기운을 용신으로 본다.

**다른 방법을 쓰면 다른 답이 나온다.** 그래서 화면 맨 위에 "억부용신법
기준입니다. 조후·병약 등 다른 방법을 쓰면 답이 달라질 수 있습니다"를
적어둔다. 숨기고 정답인 척하는 것이 이 앱에서 가장 하면 안 되는 일이다.

**판정만 던지지 않는다.** "당신은 신강입니다"는 아무 도움이 안 된다.
득령·득지·득세를 각각 O/X 로 보여주고, 자리별 계산을 펼쳐볼 수 있게 한다.

```
월지 辰 편인 인성  +3     ← 태어난 계절의 기운이라 가장 무겁다
일지 午 정관 관성  -2
년지 午 정관 관성  -1.5
시지 辰 편인 인성  +1.5
월간 庚 비견 비겁  +1
년간 庚 비견 비겁  +1
시간 庚 비견 비겁  +1
                  ────
      돕는 7.5 / 빼는 3.5 → 68% → 신강
```

무게(월지 3, 일지 2, 년·시지 1.5, 천간 1)도 화면에 적어둔다. 사용자가
동의하지 않으면 어디가 다른지 짚을 수 있어야 한다.

#### 외부 정답지가 없는 것을 어떻게 검증하나

만세력은 골든 50건으로 교차 검증했지만 용신은 그럴 수 없다. 대신
**성질**로 검증한다. 어떤 판정법을 쓰든 반드시 지켜야 하는 것들이다.

1. 비겁·인성만으로 채운 명식은 반드시 신강 (점수 1.0)
2. 식상·재성·관성만으로 채운 명식은 반드시 신약 (점수 0.0)
3. 돕는 자리를 하나 늘리면 점수가 반드시 올라간다 (단조성, 8단계 검증)
4. 신강이면 빼는 기운이, 신약이면 돕는 기운이 용신이다
5. 같은 입력에 같은 결과 (난수 없음)

이 다섯이 깨지면 판정법이 무엇이든 틀린 것이다.

## 신살 — 겁주지 않는다

신살은 이름에 살(殺)이 붙어 오래 겁주는 데 쓰여 왔다. 도화살은 바람기,
역마살은 떠돌이 팔자, 백호대살은 피를 본다 하는 식이다.

실제로는 기운의 결이다. 도화는 사람을 끌어당기는 힘이고 역마는 움직이는
힘이다. 지금 세상에서 도화는 매력이고 역마는 글로벌 커리어다.

그래서 문장 규칙을 셋 두고 **테스트가 지킨다**.

1. 그 기운이 무엇인지 먼저 말한다
2. 잘 쓰일 때와 걸림돌이 될 때를 같이 적는다
3. "조심하세요" 로 끝내지 않는다

테스트는 긍정 단어 화이트리스트가 아니라 **재해석 표지**를 본다 —
"오히려", "실제로는", "~가 아니라" 처럼 통념을 뒤집는 말이 살(殺) 이름이
붙은 항목마다 반드시 하나는 있어야 한다. 옛 공포 표현("피를 본다")은
인용해서 부정할 때만 허용한다.

판정에는 근거를 붙인다. "도화살이 있습니다" 로는 확인할 방법이 없지만
`도화 · 년지 酉 기준 → 월지 午` 는 다른 곳과 대조할 수 있다.

넣은 것 13종: 도화 · 역마 · 화개 · 천을귀인 · 문창귀인 · 금여 · 양인 ·
홍염 · 원진 · 귀문관 · 백호대살 · 괴강 · 천라지망.

삼재·대장군처럼 해마다 바뀌는 것은 넣지 않았다. 원국의 성질이 아니고
공포 마케팅의 대표 항목이라 이 앱과 맞지 않는다.

## 리포트 — 계산 근거를 같이 싣는다

관객이 부모님 세대다. 그 세대는 스크롤을 안 하고 종이를 본다.
브라우저 인쇄로 A4 문서가 나오고 "PDF로 저장" 하면 파일이 된다.
외부 라이브러리 없이 print CSS 만 쓴다.

다른 사주 리포트와 다른 점은 **결론만 적지 않는다**는 것이다.

```
계산 근거
  출생 당시 한국 표준시 UTC+9:30 (서머타임 적용 중)
  진태양시 보정 −62분 05초 — 출생지 126.978°E 기준
  야자시 일주 유지 · 균시차 미적용
  태어난 시각 없이 계산했습니다. 대운 타임라인은 시각과 무관하므로
  그대로 정확하고, 시주와 오행 분포만 여섯 자 기준입니다.
```

"당신은 신강입니다" 만 적힌 문서는 다시 읽을 이유가 없다. 근거가 적힌
문서는 나중에 다른 곳과 대조해볼 수 있다. 용신 자리별 계산도 화면에서는
접어두지만 문서에는 펼쳐서 넣는다.

## 인생 대조표 — 맞다고 말해주는 대신 직접 적게 한다

각 대운 칸을 펼치면 글 쓰는 칸이 있다. 지나온 10년에는 이렇게 묻는다.

> **1967~1976년, 실제로 무슨 일이 있었나요**
> 이직, 이사, 만남, 아팠던 일…

앞으로 올 10년에는 묻지 않는다. "무슨 일이 있었나요" 를 미래에 물으면 그건
예언을 받아적으라는 뜻이 되어버린다.

적은 것은 리포트에도 실린다 — 사주 풀이 옆에 본인이 겪은 일이 나란히 놓인다.
이 문서에서 유일하게 우리가 쓰지 않은 부분이고, 그게 이 기능의 요점이다.

저장은 이 기기의 localStorage 뿐이다. 저장 키에도 생년월일이 평문으로 들어가지
않게 공유 토큰과 같은 불투명 키를 쓴다. 다른 사람 사주로 넘어가면 그 사람의
칸은 비어 있고, 지우기 버튼은 **이 사주의 기록만** 지운다.

곁가지로 잡힌 것: `restoreSaved` 가 정의만 되어 있고 **어디서도 호출되지
않고 있었다.** 저장만 하고 복원을 안 하던 셈이다. 부팅 경로를 만들면서 같이
연결했다 — 링크가 있으면 링크로, 없으면 마지막 입력을 폼에만 채운다(자동
계산은 안 한다. 남의 기기에서 열었을 때 남의 사주가 튀어나오면 곤란하다).
