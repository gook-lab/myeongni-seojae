# 화면과 움직임

> 관객이 부모님 세대입니다. 그 전제가 화면의 거의 모든 결정을 정했습니다.

[← 명리서재](../README.md)

## 첫 화면 — 메뉴 앞에 한 장

원래는 접속하자마자 메뉴였습니다. 그런데 첫 방문자가 보는 것이 **잠긴 버튼
세 개**였습니다 — 오늘·궁합·신년은 사주를 봐야 열리기 때문입니다. 무엇을 하는 곳인지
모르는 사람에게 잠긴 문 셋을 먼저 보여준 셈이었습니다.

지금은 하나만 물습니다. 대신 이 앱이 **무엇을 하지 않는지**를 먼저 말합니다.

> 겁주지 않습니다 — 살(殺)이 붙은 이름도 기운의 결로 읽습니다
> 점수를 매기지 않습니다 — 사람을 숫자 한 개로 줄이지 않습니다
> 생년월일을 가져가지 않습니다 — 계산은 전부 이 브라우저 안에서 끝납니다

이 세 줄이 이 프로젝트의 시작점인데 여태 어느 화면에도 적혀 있지 않았습니다.

### 오늘의 일진은 장식이 아닙니다

가운데 낙관처럼 찍히는 글자는 **방금 계산한 오늘의 일진**입니다. 눌러보면
다시 찍힙니다.

일주는 율리우스일 하나로 정해져서 절기표도 음력 자료도 필요 없습니다. 그
부분만 `core/day-cycle.ts`로 떼어놨기 때문에, 첫 화면이 23.6KB짜리
절기표를 받지 않고도 "이건 실제로 계산합니다"를 보여줄 수 있습니다.

E2E는 화면이 말하는 일진을 **율리우스일로 다시 구해서** 맞춰봅니다.
하드코딩이면 그 검사를 통과할 수 없기 때문입니다.

### 문턱이 되면 안 됩니다

성공 기준이 "부모님께 링크를 보내드렸을 때 도움 없이 결과 화면까지
도달하신다"입니다. 한 장을 더 두면 탭이 하나 늘어나기 때문입니다. 그래서 두 길을
열어뒀고, 둘 다 테스트로 지킵니다.

| | 동작 |
|---|---|
| 공유 링크로 열면 | 인트로를 아예 거치지 않고 결과로 |
| 한 번 본 사람 | 다음부터 메뉴로 바로 |

모바일(320×658)에서 「시작하기」가 스크롤 없이 보이는 위치(y=596)에 있습니다.

## 화면 구조 — 쌓지 않고 갑니다

```
홈  [사주 보기]  [오늘] [궁합] [신년]
      ↓            ↓      ↓      ↓
    입력                별도 화면
      ↓
    인생 타임라인 · 사주팔자        (2.9 화면)
      ├─ [상세 풀이 보기]  용신 · 궁위 · 오행 균형 · 풀이
      └─ [리포트 · 인쇄]   A4 문서 (브라우저 인쇄 → PDF)
```

원안 와이어플로우 그대로입니다. 한 번 부가 기능을 결과 페이지 하단에 탭으로
쌓아봤는데, 결과 화면이 3.8화면 길이에 버튼 18개가 되면서 대운 타임라인이
주인공 자리를 잃었습니다.

**문제는 기능 개수가 아니라 쌓아놓은 것이었습니다.** 홈에서 갈라놓으니
기능을 하나도 잃지 않으면서 타임라인 화면이 깨끗해졌습니다. 결과 화면의
섹션은 셋뿐입니다 — 인생 타임라인(주인공), 사주팔자(근거), 풀이(원국 해석).

부가 화면은 원국이 있어야 열려요. 사주를 먼저 보지 않으면 잠겨 있고,
눌러도 입력 화면으로 보냅니다.

상세 풀이도 별도 화면입니다. 궁위·오행 균형·풀이를 결과 화면에 쌓았더니
5.2화면이 됐고, 원안대로 갈라놓으니 2.9 + 2.6으로 나뉘었습니다.

## 움직임 — 라이브러리 없이

애니메이션을 넣자는 이야기가 나와서 framer-motion을 **실제로 재봤습니다.**

```
진입 청크   243KB → 373KB   (+130KB, gzip +42.5KB)
```

관객이 구형 안드로이드 + 느린 회선이기 때문입니다. 애니메이션 하나에 낼 값이 아니라
전부 CSS로 만들었습니다.

```
진입 청크   243.07KB → 243.34KB   (+0.27KB)
CSS         20.10KB → 20.92KB     (gzip +0.32KB)
```

> 그 뒤로 인트로·처리방침·용어 화면이 붙어 진입 청크는 지금 **245KB**입니다.
> 예산은 여전히 250KB이고, 본문 덩어리 화면은 전부 나눠 받습니다.

결도 다릅니다. 이 앱은 한지와 먹의 화면이라 튀어오르거나 흔들리지 않습니다.
붓이 지나가듯 한 방향으로, 짧게. 최대 이동은 8px이고 스케일은 안 씁니다.

| 어디 | 무엇 |
|---|---|
| 화면 전환 | 260ms 페이드 + 8px 상승. 입력 → 결과가 이 앱에서 제일 중요한 전환이라 같은 route 안에서도 키를 가른다 |
| 타임라인 칸 | 위에서부터 45ms 간격으로 순차 등장. 여덟 번째부터는 더 늦추지 않는다 — 열 칸을 다 기다리면 애니메이션이 아니라 지연이다 |
| 세로선 | 위에서 아래로 그어진다. 인생이 흐르는 방향 |
| 힘 막대 | 왼쪽에서 차오른다. `scaleX` 라 리플로우가 없다 |
| 칸 펼침 | `grid-template-rows: 0fr → 1fr`. 내용 높이를 몰라도 auto 로 열린다 |
| 계산 중 | 먹이 번졌다 옅어진다. 느린 회선에서 몇 초 걸리는 구간이라 멈춘 게 아니라는 표시가 필요하다 |

### 끝나면 제자리에 있어야 합니다

등장 애니메이션은 `opacity: 0`에서 시작합니다. 어떤 이유로 애니메이션이
안 끝나면 **글자가 영영 안 보여요.** 그래서 keyframes에 `from`만 두고
`to`를 비워뒀습니다 — 끝 상태가 요소 본래의 스타일이라, 애니메이션이 아예
안 돌아도 그냥 보여요. E2E가 열 칸 전부의 최종 opacity를 확인합니다.

### 움직임을 원하지 않는 사람

관객이 부모님 세대라 `prefers-reduced-motion`은 취향이 아니라 접근성입니다.

원래 있던 규칙은 duration만 지우고 있었습니다. **순차 등장을 넣으면서 그게
버그가 됐습니다** — delay가 남아 마지막 칸이 315ms 동안 안 보여요. delay와
반복 횟수까지 같이 지우도록 고쳤고, 그 사실을 테스트로 박아뒀습니다.

E2E는 여기서 한 번 더 갈려요. Playwright는 클릭 전에 애니메이션이 멎기를
기다려서, 등장 애니메이션을 넣자 **28초에서 58초로** 늘었습니다. 그래서 플로우
테스트는 전부 움직임을 끄고 돌습니다. 속도만 얻는 게 아니라 **움직임을 줄인
설정에서도 모든 플로우가 되는지가 매 실행마다 확인되습니다.**

곁가지로 하나 걸렸습니다. `playwright.config.ts`의 `use: { reducedMotion }`이
1.62.1에서 적용되지 않습니다 — 최상위에 넣어도 프로젝트 use에 넣어도
`matchMedia`가 false입니다. 같은 실행에서 `page.emulateMedia()`로 직접 걸면
true가 됩니다. 안 먹는 설정을 남겨두면 "움직임을 끄고 돈다"가 거짓말이
되니까 `e2e/fixtures.ts`에서 page마다 직접 걸습니다.

## 결과 링크 공유 — 정직한 절충

서버가 없습니다. 그러니 링크로 결과를 복원하려면 **링크 안에 입력이 들어 있어야
합니다.** 이건 암호화가 아닙니다. 링크를 받은 사람은 생년월일시를 되읽을 수 있고,
되읽을 수 있어야 링크가 작동합니다. 그래서 버튼 밑에 그대로 적었습니다.

> 링크에는 생년월일이 글자로 들어가지 않지만,
> **링크를 가진 사람은 이 사주를 그대로 볼 수 있습니다.**

그럼 왜 `?year=1990&month=5`로 안 하는가. 막으려는 게 다른 것이기 때문입니다 —
**지나가다 읽히는 것**입니다. 주소창과 방문 기록, 채팅 미리보기, 오류 리포트.

| 결정 | 이유 |
|---|---|
| 쿼리가 아니라 **프래그먼트(#)** | 서버로 전송되지 않고 Referer 에도 안 실린다. 정적 호스팅 로그에 안 남는다 |
| 비트로 접어 base64url | `#r=E5VxS8AA-Ts` — 11글자. 어깨너머로 안 읽히고, 채팅에서 안 잘린다 |
| 체크섬 **16비트** | 8비트면 손상된 링크가 256분의 1로 통과한다. 통과하면 조용히 *다른 사람 사주*가 나온다 |
| 표준형 검사 | base64 마지막 글자의 잉여 비트만 바뀐 토큰은 체크섬이 못 잡는다. 다시 접어 원본과 대조해 모든 글자가 의미를 갖게 했다 |
| 이름은 안 담는다 | 누구 것인지가 붙는 순간 성질이 달라진다 |

토큰 전 위치 × 전 글자로 한 글자씩 바꿔보는 전수 검사에서 **통과하는 변형이
하나도 없습니다.** 잘린 링크는 반드시 실패하고, 실패하면 이렇게 말합니다 —
"링크가 손상됐습니다. 메신저에서 주소 뒤가 잘렸을 수 있습니다."

### 여기서 실제 구멍이 하나 나왔습니다

원래 설계는 "URL 해시를 아예 쓰지 않는다"였습니다. Sentry가 `location.href`를
이벤트에 담기 때문입니다. 이제 해시를 쓰기로 했으니 세탁이 되는지 확인하는
테스트를 먼저 썼는데 — **브레드크럼에서 실패했습니다.** `scrubUrl`은 프래그먼트를
버리지만, navigation 브레드크럼의 `to`/`from`은 `scrubDeep`을 거쳐 날짜만
지워지고 있었습니다. 토큰은 날짜처럼 안 생겼으니 그대로 남았습니다.

`scrubDeep`이 URL처럼 생긴 문자열을 URL로 세탁하도록 고쳤습니다.


## 말과 행동을 맞춥니다

### 색 대비 — 취향이 아니라 판독성

관객이 부모님 세대입니다. 흐린 글씨는 "차분한 톤"이 아니라 안 보이는 글씨입니다.
그런데 색은 디자인 시안에서 그대로 가져오게 되고, 가져온 값이 기준을
넘는지는 아무도 안 재봅니다. 재보니 셋이 WCAG AA(본문 4.5:1)에 미달이었습니다.

| 토큰 | 전 | 후 | 대비 |
|---|---|---|---|
| `ink-faint` (약한 글씨) | `#8a7a63` | `#766855` | 3.85 → **5.01** |
| 금 | `#75787e` | `#696c71` | 4.10 → **4.88** |
| 토 | `#8c6b2f` | `#85652c` | 4.56 → **4.99** |

하필 `ink-faint`가 11~12px 작은 글씨 전용이라 **낮은 대비와 작은 크기가
겹쳐 있었습니다.** 한지의 결은 그대로 두고 명도만 낮췄습니다.

`test/contrast.test.ts`가 **styles.css를 직접 읽어** 계산합니다. 토큰을
손보는 순간 걸려요. 사람이 눈으로 못 잡는 종류의 실패라 테스트가 본체입니다.

### 폰트를 우리 쪽에서 냅니다

처리방침 화면에 "아무 데도 보내지 않습니다"라고 적어놓고, 정작 페이지를
열 때마다 `fonts.googleapis.com`으로 요청이 나가고 있었습니다. 생년월일이
실려 가는 건 아니지만 IP와 접속 사실은 남습니다. **한 말과 하는 일이 달랐습니다.**

길은 셋이었습니다.

1. 문구를 고쳐요 — 쉽지만 이 앱의 이유를 깎습니다
2. 웹폰트를 버려요 — 기기마다 글꼴이 달라져 한지의 결이 사라집니다
3. **우리가 호스팅합니다** ← 이걸 골랐습니다

한글 폰트는 통으로 받으면 수 MB지만 유니코드 구간별로 쪼개져 있습니다
(고운바탕은 굵기당 95조각). 그 `unicode-range` 규칙은 우리가 호스팅해도
그대로 동작해서, **브라우저는 화면에 실제로 쓰인 글자가 든 조각만 받습니다.**
저장소에는 3.4MB를 두지만 방문자는 몇 개만 받습니다.

`pnpm fonts`로 다시 받습니다. 그리고 두 곳에서 막습니다.

- `bundle.test.ts` — 빌드 산출물에 외부 호스트 문자열이 있으면 실패합니다
- `intro.spec.ts` — 실제 브라우저에서 localhost 밖으로 나간 요청이 있으면 실패합니다

CDN 한 줄이면 조용히 되돌아가는 종류라, 문서가 아니라 게이트로 막습니다.


## 초기화 — 남는 것 없이

사주를 한 번 보고 나면 초기화할 방법이 없다는 지적을 받았습니다. 사실
「다른 사람 사주 보기」가 있었는데 두 가지가 문제였습니다.

### 이름이 하는 일을 안 담고 있었습니다

"다른 사람 사주 보기"는 **남의 사주**를 보는 것으로 읽혀요. 처음부터
다시 시작한다는 뜻으로는 안 읽혀요. 하는 일은 같은데 이름이 그걸 가리지
못했습니다 — 「처음부터 다시 — 다른 사주 보기」로 바꿨습니다.

### 주소에 앞 사람이 남아 있었습니다

더 조용한 쪽이었습니다. 공유 링크(`#r=…`)로 들어와서 「다시 보기」를 누르면
화면은 비워지는데 **주소에는 토큰이 그대로 남습니다.** 새로고침 한 번에
앞 사람 사주가 되살아납니다. `reset()`이 프래그먼트도 지우도록 고쳤고,
E2E가 실제로 새로고침해서 확인합니다.

### 데이터 삭제 — 안내문 대신 삭제 버튼

처리방침의 "지우고 싶습니다" 문답이 이렇게 적혀 있었습니다.

> 전부 지우시려면 브라우저에서 이 사이트의 데이터를 삭제하시면 됩니다.

관객이 부모님 세대입니다. 브라우저 설정에서 사이트 데이터를 찾으라고 하면
못 지웁니다. **우리가 만든 것이니 지우는 버튼도 우리가 제공합니다.**

「이 기기에서 전부 지우기」가 저장한 셋(마지막 입력·인생 기록·첫 화면을
봤다는 표시)과 주소의 토큰을 함께 지우고 첫 화면으로 돌려보냅니다. 되돌릴
수 없으니까 한 번 물습니다 — 지우기가 곧바로 눌리는 자리에 있으면 손이
미끄러집니다.

E2E는 지운 뒤 `localStorage`에 `myeongri.`로 시작하는 키가 하나도
남지 않는지까지 봅니다.


## 공유 카드 — 퍼뜨리는 그림이라

대운 칸 하나를 이미지로 만들어 공유하는 기능이 있습니다. 만들어놓고 **한 번도
눈으로 본 적이 없었습니다.** 꺼내 보니 맨 아래 글이 이렇게 끝나고 있었습니다.
